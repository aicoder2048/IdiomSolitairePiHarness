# Issue #10 — `/hint` candidates in a TUI overlay

## Goal and boundaries

When `/hint` obtains usable candidates, show a dismissible overlay only in `ctx.mode === "tui"`. Its content, in order, is:

```text
💡 提示
心想事成
心旷神怡
本轮 0 分，Bot 接龙中…
```

Use the actual returned candidates, one per line. Any key closes the component through the factory's `done()` callback. All other modes retain exactly the existing `pi.appendEntry` hint card. Hint generation/filtering, scoring, round creation, prompt contents, other commands, and model context remain unchanged.

## Current ownership and API findings

- `src/extension/index.ts`: `/hint` calls `game.hint(3, ctx.signal)` and passes its outcome through synchronous `report()`, then `startBotTurn()` sends the returned prompt. `report()` currently writes the two-line hint card for `bot_turn` outcomes with nonempty hints, resets nudges, and refreshes the board.
- `src/engine/game.ts`: `hint()` makes one hint-model call, filters candidates, and starts a zero-point human hint turn. Empty/error responses produce an error outcome, not a new round. Do not edit this file.
- No generic overlay helper exists in `src/extension/`.
- Installed Pi 1.0.1 supports `ctx.ui.custom<T>((tui, theme, keybindings, done) => component, { overlay: true })`, returning a promise resolved on completion. Components supply `render(width)`, `invalidate()`, and optionally `handleInput(data)`.
- `tests/extension/fake-pi.ts` defaults to `mode: "rpc"` with `hasUI: true`; this intentionally demonstrates why `hasUI` alone is not an overlay guard.
- Existing `/hint` regression in `tests/extension/extension.test.ts` expects the legacy card and must continue passing in the default fake mode.

## Explicit choices

1. Use a small reusable, static text panel, not a selection menu, scrolling interface, or new dependency. Default Pi overlay placement is sufficient; no custom positioning or overlay handles.
2. Do not await dismissal before sending the Bot prompt or returning from the hint command. The overlay is presentation only; the Bot must start while it remains open. Keep `report()` synchronous and launch the custom UI without awaiting its completion. Attach a rejection handler that reports a Chinese UI error via the existing notifier; it must not alter game state or send another prompt.
3. Replace only successful hint display. No candidates, model errors, busy/game-over outcomes, and all other command output follow the existing paths unchanged.
4. No extra hint card is appended in TUI. The overlay does not enter model context or persist as a hint card. Normal later round cards remain unchanged.
5. Document the overlay/card exception in the engineering rules, since rule 5 currently describes human-facing output as appendEntry cards generally.

### 3. New `src/extension/panel.ts` and `tests/extension/panel.test.ts`

- Export a reusable helper such as `createPanel(title: string, lines: readonly string[], done: () => void): Component` using the Pi TUI `Component` type.
- Render the title followed by the supplied text lines. Keep styling/layout minimal; no extra instruction after the required final line. A simple padded or unbordered text component is sufficient.

## Test matrix and assertions

1. **Successful TUI hint:** script two valid candidates; call `/hint`; assert exactly one `ui.custom` call with `overlay: true`, no hint appendEntry, exactly one hint LLM call (`llm.roles()` equals `["hints"]`), and exactly one `sendUserMessage` containing the existing target character. The command completes and these assertions hold while the custom promise is still unresolved.
2. **Overlay contents/dismissal:** invoke the captured factory, render at ample width, assert `💡 提示`, each candidate on its own line in original order, and exact final text `本轮 0 分，Bot 接龙中…`. Send an ordinary key and verify completion. Closing does not add model calls/messages or mutate scores. Direct panel tests additionally exercise Escape/Enter and repeated input using fresh components.
3. **Non-TUI fallback:** parameterize RPC/JSON/print, retaining default fake coverage. Assert zero custom calls and the exact entry `{ customType: "idiom-card", data: { title: undefined, lines: ["提示：心想事成、心旷神怡", "你使用了提示（本轮 0 分）"] } }`. Each successful hint calls the hint model once and sends one Bot message. Include a no-UI fallback case by setting `hasUI: false`.
4. **Turn/scoring independence:** with a TUI panel still open, confirm another human input is busy and Bot can submit a valid candidate normally (e.g. `心想事成` for initial target `心`). Inspect normal round output/status for zero human hint points and normal Bot settlement. Account separately for the judge call caused by the Bot submission. Dismissing later cannot create another turn/message.
5. **Unsuccessful hints:** in TUI, empty/invalid candidates or a scripted model error yield the existing notification, no overlay/card, no Bot message; no change to engine filtering. A busy `/hint` likewise creates no new display/model call/message.
6. **Panel widths:** test Chinese, the emoji title, and long text at ordinary and tiny widths (including 0, 1, 2); assert `visibleWidth(line) <= width`, no exceptions, and full untruncated content at ample width. Rendering/invalidation never calls `done()`.
